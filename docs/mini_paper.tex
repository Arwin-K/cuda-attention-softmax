\begin{abstract}
\justifying
\textbf{Context:} Causal scaled softmax combines scaling, future-position
masking, stable exponentiation, row-wise maximum and denominator reductions,
synchronization, and global-memory traffic. This makes it a compact subject for
studying how CUDA design choices translate into kernel and application
performance.
\textbf{Objective:} This study evaluates how work decomposition, reduction
communication, and launch configuration affect a fused forward-pass FP32
causal scaled-softmax operator, and how much isolated-kernel improvement
survives in explicit transformer attention.
\textbf{Method:} One evolving implementation progressed from one thread per
row to one block per row with full shared-memory trees and then compact
warp-shuffle reductions. Seven sequence lengths, three launch sizes, three
isolated-softmax paths, and three attention paths were measured. Each
configuration received 25 warmups and 100 CUDA-event observations in one
NVIDIA Tesla T4 session; these observations describe within-session variation,
not independent replications.
\textbf{Results:} All 88 structured softmax cases passed at
$\mathrm{rtol}=10^{-5}$ and $\mathrm{atol}=10^{-6}$, with maximum absolute error
$3.5763\times10^{-7}$. The warp kernel was 3.22--8.92$\times$ faster than the
row-serial implementation, 1.07--1.91$\times$ faster than the shared-tree
implementation, and 1.40--3.94$\times$ faster than equivalent PyTorch eager
softmax. Explicit attention improved by 1.54--2.31$\times$, but PyTorch
scaled-dot-product attention remained faster at every tested shape.
\textbf{Conclusion:} Cooperative work mapping and compact warp communication
materially improved the isolated operator and an explicit composition in the
measured session. Unchanged matrix multiplications and attention-wide fusion
limited application-level gains, so the evidence does not establish production
superiority or cross-device generality.

\vspace{0.2em}
\noindent\textbf{Keywords:} CUDA; GPU optimization; stable softmax; causal
attention; transformer attention; kernel fusion; parallel reduction.

\section{Introduction}

Transformers organize sequence modeling around attention, which exposes
parallel work across tokens while learning data-dependent relationships
\cite{vaswani2017}. Scaled dot-product attention is
\begin{equation}
\operatorname{Attention}(Q,K,V)=
\operatorname{softmax}\!\left(\frac{QK^{T}}{\sqrt{d}}+M\right)V,
\label{eq:attention}
\end{equation}
where $d$ is the head dimension and $M$ excludes invalid positions. In causal
self-attention, a query at position $i$ may attend only to keys at positions
$j\le i$. PyTorch exposes this operation through scaled-dot-product attention
(SDPA) and can dispatch to optimized backends depending on the inputs and
runtime \cite{pytorch_sdpa}.

Equation~\ref{eq:attention} contains two matrix multiplications around a
reduction-heavy normalization. Softmax requires a maximum reduction for
numerical stability, exponentiation, a denominator reduction, and final
normalization. A framework composition also performs scaling and causal
masking as separate tensor work. This structure makes causal softmax a compact
case study in GPU work decomposition, coalesced memory access, synchronization,
shared memory, register-local partials, and warp communication.

This work studies one primary CUDA source file through Git history rather than
maintaining unrelated ``naive'' and ``optimized'' implementations. Five
research questions (RQs) separate numerical behavior, kernel mechanisms,
launch policy, framework comparison, and application translation:

\begin{enumerate}
\item[\textbf{RQ1}] Does the operator preserve the intended causal
scaled-softmax contract for the structured FP32 test domain?
\item[\textbf{RQ2}] How much do cooperative work decomposition and compact
warp communication contribute to latency reduction?
\item[\textbf{RQ3}] Is one threads-per-block choice optimal across the tested
sequence lengths?
\item[\textbf{RQ4}] How does the fused operator compare with equivalent eager
and compiled framework softmax paths?
\item[\textbf{RQ5}] How much isolated-softmax improvement survives in explicit
attention, and how does that path compare with production SDPA?
\end{enumerate}

The contributions are: (1) an inspectable fused causal scaled-softmax operator;
(2) commit-linked comparisons of row-serial, shared-tree, and warp-reduction
designs; (3) controlled launch and framework comparisons; (4) integration into
explicit attention with a production SDPA baseline; and (5) a reproducible
evidence archive containing raw samples, environment metadata, figures,
profiler exports, and the executed experiment notebook.

The claims are deliberately bounded. All timings were collected in one session
on one Tesla T4. Repeated CUDA-event observations reveal conditional timing
spread but do not constitute independent machines or sessions. The paper
therefore reports descriptive medians, quartiles, ratios, and rank separation,
while reserving confirmatory inference for a replicated design.

\section{Background and Related Work}

\subsection{Stable Causal Softmax}

For logits $x_1,\ldots,x_n$, numerically stable softmax subtracts the row
maximum $m$:
\begin{equation}
p_i=\frac{\exp(x_i-m)}{\sum_j\exp(x_j-m)},\qquad m=\max_j x_j.
\label{eq:stable}
\end{equation}
Multiplying numerator and denominator by $\exp(-m)$ shows that the probability
is mathematically unchanged. Numerically, the largest exponential argument is
zero and all others are non-positive, preventing large positive logits from
overflowing the exponential. Stable log-sum-exp and softmax evaluation has
been studied directly \cite{blanchard2019}, and online normalization work
demonstrates how reorganization can reduce memory access \cite{milakov2018}.

Floating-point addition is not associative, so different parallel reduction
orders need not match bit-for-bit. CUDA and PyTorch document the resulting
rounding and reproducibility constraints \cite{cuda_fp_math,cuda_best_practices,
pytorch_numerical,pytorch_reproducibility}. Accordingly, this study fixes
error tolerances before performance evaluation rather than requiring exact
equality or weakening tolerances after observing results.

\subsection{CUDA Reductions and Warp Communication}

CUDA groups threads into blocks and blocks into a grid. Threads in a block can
cooperate through shared memory and block-wide barriers; hardware executes
threads in warps, conventionally 32 lanes on the tested architecture
\cite{cuda_programming_guide}. A block reduction can combine one partial per
thread through a shared-memory tree. Warp shuffle operations instead exchange
register values within a warp, avoiding a shared-memory write--barrier--read
sequence at each intra-warp reduction step \cite{cuda_warp_shuffle}. A compact
two-level design can reduce within each warp, store one result per warp in
shared memory, and use the first warp for the final block result.

Parallel reduction is a well-established CUDA optimization subject. Harris
develops the canonical sequence of mapping, addressing, and warp-tail
transformations, while CUB packages architecture-tuned block collectives
\cite{harris2007,cub_block_reduce}. The hand-written reduction here is intended
to expose those engineering choices. It is not evidence that a bespoke kernel
would outperform a matched CUB implementation.

Performance does not follow from occupancy or thread count alone. Block size,
register use, shared memory, coordination, and row length interact, so launch
configuration must be measured rather than inferred \cite{cuda_occupancy,
cuda_best_practices}.

\subsection{Fusion and Attention Systems}

Kernel fusion can reduce intermediate storage and launch overhead by retaining
related work within one kernel. FlashAttention showed that IO-aware tiling can
substantially improve exact full attention by reducing high-bandwidth-memory
traffic \cite{flashattention2022}; FlashAttention-2 further improved work
partitioning and parallelism \cite{flashattention2}. The present operator is
deliberately narrower: it fuses the scaled causal softmax stage but leaves
$QK^T$ and $PV$ to PyTorch. This boundary makes the difference between a
microkernel result and a full-attention result explicit.

Memory-efficient attention can avoid retaining the full quadratic matrix even
when arithmetic remains quadratic \cite{rabe2021}. Likewise, cuDNN and Triton
illustrate two different routes to maintainable optimized kernels:
architecture-tuned reusable libraries and tile-level compiler abstractions
\cite{cudnn2014,triton2019}. These systems motivate stronger future baselines;
their absence is treated as a construct-validity limitation.

\subsection{Framework Compilation and Empirical Rigor}

PyTorch eager execution, graph compilation, and specialized attention backends
control different fusion boundaries. PyTorch~2 uses bytecode capture and a
compiler stack to optimize graphs while retaining Python flexibility
\cite{pytorch2_2024}. A comparison against eager execution measures replacement
of a multi-operator composition; a comparison against steady-state
\code{torch.compile} asks whether compilation can remove similar overhead; and
SDPA evaluates a broader production-oriented boundary.

Systems benchmarking is sensitive to layout, clocks, runtime state, and
measurement order. Seemingly innocuous environmental changes can reverse
conclusions, motivating raw-data retention, randomized independent sessions,
and explicit experimental units \cite{mytkowicz2009,stabilizer2013}. The
Roofline model supplies useful memory-versus-compute context
\cite{roofline2009}, but the available profiler fields are insufficient for a
quantitative Roofline placement. No bottleneck classification is claimed.

\section{Methodology}

\subsection{Operation Contract}

For $Q,K,V\in\mathbb{R}^{B\times H\times S\times D}$, the score tensor is
flattened from $[B,H,S,S]$ to $[R,S]$, where $R=BHS$. For row $r$, the query
position is
\begin{equation}
q_r=r\bmod S.
\end{equation}
Only columns $j\le q_r$ are allowed. Given a finite positive scale $\alpha$,
the fused operator computes
\begin{align}
m_r &= \max_{j\le q_r}(\alpha s_{r,j}),\\
z_r &= \sum_{k\le q_r}\exp(\alpha s_{r,k}-m_r),\\
p_{r,j} &=
\begin{cases}
\exp(\alpha s_{r,j}-m_r)/z_r,&j\le q_r,\\
0,&j>q_r.
\end{cases}
\label{eq:fused}
\end{align}
The output preserves shape, dtype, and device. The implementation accepts
contiguous two-dimensional FP32 CUDA tensors and implements forward execution
only.

The C++ boundary rejects CPU, noncontiguous, non-FP32, non-matrix, or empty
inputs; nonpositive or nonfinite scales; and unsupported launch sizes. A CUDA
device guard selects the input device, allocation inherits the input options,
and launch occurs on PyTorch's current CUDA stream. Immediate launch errors are
reported through the extension boundary. These checks separate the public
framework contract from the device algorithm.

stages scaled values, applies the causal predicate, performs maximum and sum

\subsection{Final Kernel Procedure}

Algorithm~\ref{alg:fused} states the final block-per-row procedure without
committing to CUDA syntax. Thread $t$ visits $t,t+B,t+2B,\ldots$, where $B$ is
the block size. Inactive lanes contribute $-\infty$ to maximum reduction and
zero to sum reduction, which preserves the full-warp shuffle mask.

\begin{figure}[t]
\centering
\begin{minipage}{0.97\columnwidth}
\footnotesize
\refstepcounter{algorithm}\textbf{Algorithm \thealgorithm: Fused causal
scaled softmax}\label{alg:fused}
\begin{enumerate}
\setlength{\itemsep}{0pt}
\setlength{\parsep}{0pt}
\item Assign block $r$ to row $r$; set $q=r\bmod S$.
\item Each thread stages allowed $\alpha X_{rj}$ in output scratch, writes zero
for $j>q$, and accumulates a local maximum.
\item Reduce maxima within warps; publish one value per warp; let the first
warp reduce those partials to obtain $m_r$.
\item Each thread overwrites allowed scratch values with
$\exp(\alpha X_{rj}-m_r)$ and accumulates a local sum.
\item Repeat the two-level warp reduction to obtain denominator $z_r$.
\item Each thread overwrites its allowed values with $Y_{rj}/z_r$.
\end{enumerate}
\end{minipage}
\caption*{Pseudocode for the final kernel. The output allocation is reused as
scratch for scaled values and stable exponentials.}
\end{figure}

Output reuse removes a separate temporary allocation but imposes three
barrier-protected invariants: all staged values must precede consumption of the
row maximum; the cross-warp array cannot be reused until the maximum has been
read; and all exponentials must precede consumption of the denominator. For
$B=128$, four FP32 warp partials require 16 bytes of dynamic shared memory;
$B=256$ and $B=512$ require 32 and 64 bytes, respectively. Per row, the method
performs three strided passes and $O(S)$ arithmetic with $O(\log 32)$
intra-warp steps plus one compact cross-warp reduction. These counts describe
work and storage, not measured latency.

\subsection{Hypotheses}

Five hypotheses were evaluated after evidence collection:

\begin{enumerate}
\item row-serial work scales poorly as row length increases;
\item one block per row improves sufficiently long rows despite coordination;
\item warp reductions improve on full shared-memory trees;
\item the preferred block size varies with sequence length; and
\item isolated-softmax speedup usually exceeds complete-attention speedup.
\end{enumerate}

\subsection{Correctness Protocol}

The custom output was compared with an independent PyTorch composition at
$\mathrm{rtol}=10^{-5}$ and $\mathrm{atol}=10^{-6}$. Sequence lengths were
31, 32, 33, 63, 64, 127, 128, 255, 511, 768, and 1023. Eight input families
covered normal random values; random values multiplied by 10, 100, and 1000;
zeros; equal values; one dominant positive value; and one dominant negative
value. Tests checked numerical closeness, exact causal zeros, approximate row
sums of one, finiteness, shape, dtype, and device. Complete attention was also
compared with explicit PyTorch attention and SDPA.

\subsection{Benchmark Protocol}

The isolated-softmax experiment used FP32, $R=8S$, scale $1/\sqrt{64}$, and
$S\in\{128,255,512,768,1024,1536,2048\}$. Attention used batch 1, eight
heads, and head dimension 64. Inputs, masks, and allocations were outside the
timed interval. Each case used 25 untimed warmups followed by 100 CUDA-event
samples. The median was the primary latency statistic, with the 25th and 75th
percentiles retained. CUDA synchronization ensured that device completion was
included. The initial \code{torch.compile} call was excluded from steady-state
latency and recorded as a separate compile warmup \cite{cuda_events,
pytorch_cuda_event,pytorch_cuda_synchronize,pytorch_compile}.

Every result row records its Git revision, implementation, shape, dtype,
warmups, iterations, device, compute capability, PyTorch version, CUDA version,
and timestamp. Raw samples are preserved rather than replaced by summaries.

\section{CUDA Implementation Evolution}

\subsection{Row-Serial Baseline}

The first complete design assigned one softmax row to one CUDA thread. That
thread scanned allowed columns for the maximum, scanned again for the stable
exponential sum, and normalized the row. The mapping was simple and provided a
correct baseline, but exposed no parallelism inside a row.

\subsection{Block-Parallel Shared Trees}

The second design assigned one block to one row. Thread $t$ visited columns
$t+k\,\code{blockDim.x}$, giving neighboring threads neighboring initial
addresses while supporting arbitrary row lengths. Each thread accumulated
register-local maximum and denominator partials. Full shared-memory trees then
combined those partials, with block barriers protecting producer--consumer
boundaries. A second strided pass normalized output columns in parallel.

\subsection{Compact Warp Reductions}

The final design used \code{\_\_shfl\_down\_sync} for maximum and sum
reductions within each warp. Each warp leader wrote one value to a compact
shared array; after one block barrier, the first warp completed the cross-warp
reduction. For a 128-thread block, four warp partials require 16 bytes of
dynamic shared memory. Scaling, the causal predicate, stable maximum
subtraction, exponentiation, both reductions, and normalization remain fused in
one kernel.

Historical algorithms were recovered from commits \code{8f07d762} (row
serial), \code{f9420de0} (shared tree), and \code{a3736910} (warp reduction).
The historical rebuild applied a recorded header-only include needed by CUDA
12.8; no algorithm, workload, or tolerance was changed.

\section{Results}

\subsection{Correctness}

The CUDA test stage reported 70 passes. The structured softmax matrix contained
88 comparisons (11 lengths times 8 input families), all of which passed. The
maximum absolute error was $3.5762787\times10^{-7}$, maximum relative error was
$4.6973432\times10^{-7}$, and maximum row-sum error was
$3.5762787\times10^{-7}$. Every masked future probability was exactly zero,
and no unexpected NaN or infinity appeared. Table~\ref{tab:correctness}
summarizes the accepted evidence.

All seven complete-attention comparisons passed. Maximum absolute output error
was $2.9802322\times10^{-7}$ for custom explicit attention versus explicit
PyTorch and $7.1525574\times10^{-7}$ for SDPA versus the same reference.

\subsection{Complete Attention}

The explicit custom path computes $QK^T$, invokes the custom softmax, and then
computes $PV$. It was 1.54--2.31$\times$ faster than explicit eager attention.

with the surrounding matrix multiplications limiting the benefit of optimizing
only softmax. Production SDPA remained 1.25--2.53$\times$ faster than the
explicit custom path at every length. This is a mathematically comparable
output baseline, but not an implementation-equivalent fusion boundary: SDPA can
fuse a larger portion of attention.

\section{Discussion}

\subsection{Hypothesis Evaluation}

Table~\ref{tab:hypotheses} summarizes the evidence-bounded hypothesis outcome.
The row-serial growth trend was only partially supported because latency trends

the tested long shapes. Warp reduction and shape-dependent launch choice were
supported on the T4. The kernel-to-attention prediction was partially supported
because the kernel speedup exceeded attention speedup at six, not all seven,
matched lengths.

\subsection{Microkernel Versus Application Performance}

The historical comparison shows that work decomposition produced the largest
gain: assigning a block rather than a thread to a row exposed intra-row
parallelism. Warp communication then produced a smaller but consistently
positive improvement over a block design that was already parallel.

Application improvement was smaller because the custom kernel changes only one
stage. If fraction $f$ of baseline attention time is accelerated by factor $s$,
Amdahl's Law gives
\begin{equation}
S_{\mathrm{total}}=\frac{1}{(1-f)+f/s}.
\label{eq:amdahl}
\end{equation}
The measured relationship broadly follows this limit, although the simple
model does not reproduce every short-shape latency because launch overhead,
backend selection, and interactions among operations also matter
\cite{amdahl1967}.

SDPA's consistent advantage is a central result. The custom softmax improves an
explicit attention composition, but a production backend can optimize and fuse
across a broader boundary. A fast isolated component is therefore useful
evidence, not proof of a superior end-to-end attention implementation.

\section{Limitations}

All quantitative performance findings come from one Tesla T4 in one Colab
session. They do not establish run-to-run variability or transfer to Ampere,
Ada, Hopper, or other architectures. Managed infrastructure does not fully
control clock state, contention, or future software images. Quartiles describe
within-session samples; they are not confidence intervals across machines or
sessions.

The operator implements contiguous FP32 forward causal scaled softmax. It does
not provide backward/autograd support, dropout, arbitrary or padding masks,
variable valid lengths, or mixed precision. The flattened causal contract
assumes scores derived from $[B,H,S,S]$. Historical kernels required a recorded
header include for CUDA 12.8, so the rebuilds are algorithmically matched but
not byte-identical to their original source snapshots.

Framework comparisons were designed to perform equivalent scale, mask, and
softmax work, but framework internals can evolve. Compilation startup was
excluded from steady-state \code{torch.compile} latency and should be evaluated
separately for short-lived workloads. SDPA is an output-equivalent production
baseline, not an equal-fusion-boundary microkernel baseline.

Nsight profiled only one sequence length and four launches. Peak DRAM and SM
throughput percentages do not uniquely identify a bottleneck. Matched profiler
metrics for historical kernels and independent sessions remain future work.

\section{Conclusion and Future Work}

On the measured Tesla T4 workload, changing from row-serial to block-per-row
work delivered the largest kernel improvement, compact warp communication
improved further on full shared-memory trees, and block-size preference varied
with shape. The custom operator substantially outperformed equivalent eager
softmax and accelerated explicit attention, but did not outperform production
SDPA. The central systems result is that GPU mapping and communication choices
matter locally, while end-to-end value depends on the fraction and fusion
boundary of the larger application.

Future work should repeat the complete experiment across independent sessions
and on a newer architecture; profile shared-tree and warp kernels under matched
conditions; evaluate shape-aware launch dispatch; add FP16/BF16 accumulation
analysis and fixed error criteria; add backward/autograd support; vary batch,
head count, head dimension, and masking; and compare specialized library
operators under explicitly equivalent work.
