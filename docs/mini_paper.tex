\title{\textbf{CUDA Optimization of Fused Causal Softmax for Transformer Attention}}
\author{Arwin Karir\\\small \todoauthor{institution, program, city, country, and email}}
\date{}

\begin{abstract}
\textbf{Objective:} We evaluate how CUDA work decomposition, reduction strategy,
and launch configuration affect fused FP32 causal scaled softmax and how isolated
kernel gains translate into explicit transformer attention.
\textbf{Methods:} A single CUDA source was recovered at row-serial,
block/shared-tree, and warp-reduction commits. On one NVIDIA Tesla T4, each
configuration received 25 warmups and 100 CUDA-event samples at sequence lengths
128--2048. Correctness was checked against PyTorch with fixed FP32 tolerances.
\textbf{Results:} All 88 structured softmax cases passed. The final warp kernel
was 3.22--8.92$\times$ faster than the row-serial endpoint,
1.07--1.91$\times$ faster than the shared-tree endpoint, and
1.40--3.94$\times$ faster than equivalent PyTorch eager scale--mask--softmax.
Replacing eager softmax in explicit attention yielded a
1.54--2.31$\times$ end-to-end speedup, while PyTorch scaled-dot-product
attention remained 1.25--2.53$\times$ faster than the explicit custom path.
\textbf{Conclusion:} The combined work-mapping and communication changes
improved this T4 workload, but optimizing only softmax did not surpass a
production fused-attention baseline. Claims are limited to FP32 forward
execution, one T4 session, and the tested shapes.
\end{abstract}

\noindent\textbf{Keywords:} CUDA; GPU optimization; softmax; causal attention;
transformer attention; parallel reduction; kernel fusion.

\section{Introduction}

Scaled dot-product attention computes
\begin{equation}
\operatorname{Attention}(Q,K,V)=
\operatorname{softmax}\!\left(\frac{QK^{T}}{\sqrt{d}}+M\right)V,
\label{eq:attention}
\end{equation}
where $d$ is the head dimension and a causal mask $M$ excludes future key
positions~\cite{vaswani2017}. The two matrix multiplications are separated by a
reduction-heavy normalization stage. Softmax requires a row maximum, stable
exponentiation, a denominator sum, and normalization; causal attention also
requires triangular admissibility. This makes the middle stage a compact case
study in GPU work mapping, synchronization, memory access, and numerical
stability.

The research question is: \emph{How do GPU work decomposition, parallel
reductions, warp-level communication, and launch configuration affect fused
causal scaled softmax, and how much do those kernel-level optimizations
translate into complete transformer attention performance?} One primary CUDA
translation unit, \texttt{csrc/fused\_causal\_softmax.cu}, evolves through Git
history. Earlier algorithms are identified by commits rather than duplicated
as separately named baseline and optimized files. This keeps implementation
states, hypotheses, measurements, and interpretations auditable.

The study is intentionally narrower than FlashAttention, which fuses and tiles
a larger attention scope to reduce high-bandwidth-memory traffic
~\cite{flashattention2022,flashattention2}. Here PyTorch still performs
$QK^T$ and $PV$; only scaling, causal masking, and softmax are replaced. This
boundary makes the difference between microkernel and application speedup
explicit.

\section{Background}

\subsection{Stable causal softmax}

For logits $x_1,\ldots,x_n$, stable softmax subtracts the maximum:
\begin{equation}
p_i=\frac{e^{x_i-m}}{\sum_j e^{x_j-m}},\qquad m=\max_j x_j.
\label{eq:stable-softmax}
\end{equation}
The common factor $e^{-m}$ cancels, so the mathematical probability is
unchanged. The largest exponential argument becomes zero and the others become
non-positive, avoiding positive-argument overflow~\cite{blanchard2019}.
Different parallel reduction orders can still yield small floating-point
differences, so the study uses tolerance-based comparison rather than
bit-for-bit equality~\cite{cuda_best_practices,pytorch_numerical}.

The score tensor originally has shape $[B,H,S,S]$ and is flattened to
$[R,S]$, where $R=BHS$. For flattened row $r$, the query position is
$q_r=r\bmod S$. Given score $s_{r,j}$ and scale $\alpha=1/\sqrt d$,
\begin{equation}
p_{r,j} =
\begin{cases}
\displaystyle
\frac{\exp(\alpha s_{r,j}-m_r)}
{\sum_{k\leq q_r}\exp(\alpha s_{r,k}-m_r)}, & j\leq q_r,\\[1ex]
0, & j>q_r,
\end{cases}
\end{equation}
with $m_r=\max_{k\leq q_r}\alpha s_{r,k}$. Masked outputs must therefore be
exactly zero.

\subsection{CUDA reductions and communication}

CUDA blocks provide shared memory and block-wide synchronization, while warps
execute groups of 32 threads and support register exchange through shuffle
intrinsics~\cite{cuda_programming_guide,cuda_warp_shuffle}. The fused kernel
requires maximum and sum reductions for every row. A shared-memory tree stages
one partial per thread and uses repeated barriers. The later design first
reduces register partials within each warp, writes one value per warp to shared
memory, and lets the first warp complete the block-wide reduction. For the
measured 128-thread launch, this bridge uses four floats (16 bytes) rather than
a block-sized array.

Thread $t$ processes columns $t,t+B,t+2B,\ldots$, where
$B=\texttt{blockDim.x}$. Adjacent threads therefore begin on adjacent columns,
supporting coalesced access while covering non-power-of-two lengths
~\cite{cuda_best_practices}. Launch size remains an empirical choice:
additional threads reduce per-thread loop work but add warps and coordination,
and occupancy alone does not determine performance.

\section{Materials and Methods}

\subsection{Implementation sequence}

Three historical endpoints were rebuilt from Git:
row serial (\texttt{8f07d762}), one-block-per-row shared-tree
(\texttt{f9420de0}), and warp reduction (\texttt{a3736910}). A recorded
header-only CUDA 12.8 compatibility include was applied to the historical
checkouts; the algorithms were unchanged. Current framework and attention
measurements use the clean commit
\texttt{ca87722a00ebf585cd788c67949e7c0b32dca788}.

The final kernel performs scaling, causal masking, maximum subtraction,
exponentiation, denominator reduction, and distributed normalization in one
launch. It runs on PyTorch's current CUDA device and stream and checks launch
errors at the extension boundary. The operator accepts contiguous FP32 CUDA
scores with shape $[R,S]$, a positive finite scale, and a block size of 128,
256, or 512.

\subsection{Correctness protocol}

The structured matrix used sequence lengths 31, 32, 33, 63, 64, 127, 128, 255,
511, 768, and 1023 across eight input families: standard normal, random inputs
scaled by 10, 100, and 1000, all zeros, all equal values, one dominant
positive value, and one dominant negative value. Tests required PyTorch
agreement with $\mathrm{rtol}=10^{-5}$ and $\mathrm{atol}=10^{-6}$, exact
masked zeros, row sums near one, correct shape/dtype/device, and no unexpected
NaNs or infinities. Complete-attention outputs were also compared with an
explicit PyTorch reference.

\subsection{Performance protocol}

Measurements were collected during one Google Colab session on a Tesla T4
(compute capability 7.5) with PyTorch 2.11.0+cu128, CUDA toolkit 12.8, and
Python 3.13.15. Softmax used FP32, $\alpha=1/\sqrt{64}=0.125$,
$R=8S$, and $S\in\{128,255,512,768,1024,1536,2048\}$. Attention used
$B=1$, $H=8$, and $D=64$. The launch sweep compared 128, 256, and 512
threads; its registered aggregate rule selected 128 threads for subsequent
framework and attention measurements.

Inputs, allocations, and reusable masks were prepared outside timed regions.
Each operation received 25 warmups and 100 CUDA-event samples. Medians and
interquartile values were derived from raw samples. The first
\texttt{torch.compile} invocation was excluded from steady-state timing.
Baselines were equivalent eager scale--mask--softmax, steady-state compiled
scale--mask--softmax, explicit eager attention, and PyTorch
scaled-dot-product attention (SDPA) with zero dropout and causal semantics
~\cite{pytorch_sdpa,pytorch_compile}. SDPA may select a fused backend and is
therefore a production complete-attention baseline, not a softmax-only
comparison.

\subsection{Hypotheses}

H1 predicted poor row-serial scaling; H2 predicted a long-row advantage for
one-block-per-row decomposition; H3 predicted lower latency from warp
reductions than full shared-memory trees; H4 predicted shape-dependent launch
winners; and H5 predicted that softmax speedup would usually exceed
complete-attention speedup. Status was assigned only after artifact validation.

\section{Results}

\subsection{Correctness}

All 88 structured softmax cases passed. The maximum absolute error was
$3.5763\times10^{-7}$, the maximum relative error was
$4.6973\times10^{-7}$, and the maximum row-sum error was
$3.5763\times10^{-7}$. Every future-masked probability was exactly zero and no
unexpected NaN or infinity appeared. All seven complete-attention shapes
passed; the maximum absolute output error against explicit eager attention was
$2.9802\times10^{-7}$.

\subsection{Profiling}

\textbf{Measured:} At $S=512$, PyTorch Profiler attributed
110.207~$\mu$s of CUDA time to the fused kernel. Named device totals were
505.565~$\mu$s for custom explicit attention, 1095.195~$\mu$s for eager
explicit attention, and 408.222~$\mu$s for SDPA. Nsight Compute captured four
target launches (three warmups and one target). With 128 threads, it reported
24 registers per thread, 16 bytes of dynamic shared memory, durations of
106.976--107.584~$\mu$s, 48.33--48.79\% of peak DRAM throughput, and
56.72--57.00\% of peak SM throughput~\cite{pytorch_profiler,nsight_compute}.

\textbf{Interpretation:} The 16-byte allocation agrees with four warp partials,
but throughput percentages alone do not identify a unique memory or compute
bottleneck. Profiler captures use instrumentation conditions different from
the 100-sample benchmarks and are not substituted for benchmark medians.

\textbf{Next experiment:} Profile matched shared-tree and warp endpoints and
repeat the study on another architecture.

\section{Discussion}

H1 was \textbf{partially supported}: row-serial latency grew more sharply over
the tested endpoints, but scaling trends do not by themselves prove the
mechanism. H2 was \textbf{supported} at the measured long rows. H3 was
\textbf{supported} because warp reduction was faster than the shared tree at
all seven lengths, although matched low-level profiling is still needed to
attribute the gap specifically to fewer shared accesses or barriers. H4 was
\textbf{supported} because both 128 and 256 threads won at least one shape. H5
was \textbf{partially supported}: softmax speedup exceeded attention speedup
at six, not seven, shapes.

The endpoint comparison with the largest speedup changed both work mapping and
reduction mechanism. It is therefore more accurate to say that the combined
optimization sequence produced the largest observed gap than to attribute the
entire gap to one design decision. The smaller but consistently positive
shared-tree-to-warp result better isolates communication strategy.

The attention results illustrate Amdahl's qualitative limit
~\cite{amdahl1967}. If fraction $f$ of the original application is accelerated
by factor $S_s$, the idealized total speedup is
\begin{equation}
S_{\mathrm{total}}=\frac{1}{(1-f)+f/S_s}.
\end{equation}
The preserved Amdahl CSV is a model, not an additional measurement, because its
predictions differ from observed attention latency at some shapes. SDPA's
advantage is also not a contradiction: it can optimize a broader attention
scope and reduce materialization that remains in the explicit custom path.

\section{Limitations}

The evidence covers FP32 forward causal attention, one head dimension, one
softmax batch-head setting, seven performance lengths, and one Tesla T4 session
in a shared cloud environment. It does not establish FP16/BF16 or mixed
precision behavior, backward/autograd correctness, dropout, arbitrary masks,
energy efficiency, independent-session uncertainty, or cross-architecture
generalization. Interquartile ranges describe samples within this run and are
not confidence intervals over machines or sessions. Historical builds used a
documented header-only compatibility change. Framework versions and backend
selection can change. These constraints prohibit presenting the selected block
size or speedup ranges as universal.

\section{Conclusion}

On the measured T4 workload, the Git-traced optimization sequence made fused
causal softmax substantially faster than its row-serial and shared-tree
historical endpoints. The final kernel also beat equivalent eager PyTorch
softmax and improved explicit attention. However, production SDPA remained
faster at every tested shape. The central result is therefore scoped: GPU work
mapping and communication choices matter for the isolated operator, while
application value depends on the unoptimized work surrounding it.
